## AOA Messages

## Android Device -> NTOverAOA

### Subscribe Requests

When the android app wants to start receiving a topic, it has to send a Subscribe request to NTOverAOA that looks like for example

```json
{"subscribe":["/robot/pose", "FMSInfo/IsRedAlliance"]}
```
or

```json
{"action":"subscribe", "keys":["/robot/pose", "FMSInfo/IsRedAlliance"]}
```
this will be what we will use going forward as it provides more flexibility

### Send Requests (PUT Requests)

When the android app wants to send data back like to run an action, the message will look like

```json
{"action":"put", "key":"/RouteRoute/foo", "value": 42}
// When using structs
{"action":"put", "key":"/RoboRoute/bar", "schema":"struct Pose2d {...}", "value":{...}}
```
See [Struct Schemas](#structs) for more information on writing a schema

## NTOverAOA -> Android Device

### Listing Topics
Sometimes it is useful to know all of the currently available topics from NetworkTables, every 10 seconds a list of topics is sent
```json
{"topics":["/foo","/bar"]}
```

### Receiving a value
A value from network tables will look like this over AOA

```json
{"key":"/robot/pose","time":1234.5678,"value":42}
// When using structs
{"key":"/robot/pose","time":1234.5678,"schema":"struct Pose2d {...}","value":{...}}
```
See [Struct Schemas](#structs) for more information on writing a schema

Decoded struct value example, decoded to match the struct schema

```json
{"translation":{"x":..,"y":..}, "rotation": {...}}
```
## NetworkTables Actions Structure
The data to and from NetworkTables is split into two topics (Run, Data) for each action type (Pose, Route, Path)

All NetworkTables entries are under the `RoboRoute` table, to for example pathfind to a pose, we would first set the data topic
```json
{"action":"put", "key":"/RoboRoute/Pose", "schema":"struct Pose2d {...}", "value":{...}}
```

Then we would set the `RunPose` topic true for ~1 second, then set it false
```json
{"action":"put", "key":"/RoboRoute/RunPose", "value": true}
// ~1 second later
{"action":"put", "key":"/RoboRoute/RunPose", "value": false}
```
We can repeat these steps for the Route and Path action types

- Pose - Pose2d
- Path - String
- Route - Pose2d[]

## Structs
When using a struct for either sending or receiving, there is a schema that is attached, this is an example for a Pose2d

```json
// Example Struct Schema
"struct Pose2d {struct Translation2d {double x; double y;} translation; struct Rotation2d {double value;} rotation;}"
// A value would look like this
{"translation":{"x":1.5,"y":-2.25},"rotation":{"value":0.1234}}
```
To supply an array of structs, the schema is the same but the values are supplied as an array `[]`
